# 广东电信 IPTV 自动更新与分类设计

## 目标

将 `tv.shaowt.com` 从通用聚合源切换为广东电信 IPTV 专用播放列表。播放列表基于上游仓库 `Tzwcard/ChinaTelecom-GuangdongIPTV-RTP-List` 的全量文件 `GuangdongIPTV_rtp_all.m3u`，自动完成过滤、去重、优选、分类和 udpxy 地址转换。

最终固定输出：

- `m3u/gd-telecom.m3u`
- 访问地址：`https://tv.shaowt.com/gd-telecom.m3u`

## 数据来源

上游地址：

- 仓库：`https://github.com/Tzwcard/ChinaTelecom-GuangdongIPTV-RTP-List`
- 分支：`master`
- 输入文件：`GuangdongIPTV_rtp_all.m3u`

采用全量列表，自行进行质量优选。上游按 ffprobe 生成的 HD、SD、4K 子列表可能存在分辨率误判，不作为最终分类依据。

## udpxy 配置

新增 `config/udpxy.json`：

```json
{
  "protocol": "http",
  "host": "192.168.5.7",
  "port": 4022
}
```

RTP 地址：

```text
rtp://239.77.0.4:5146
```

转换结果：

```text
http://192.168.5.7:4022/udp/239.77.0.4:5146/
```

旁路由地址或端口变化时，只修改该配置文件。

## 过滤规则

以下条目直接删除：

- 频道名称包含 `CAVS`，这类源已知只有声音、没有画面；匹配时忽略大小写。
- 频道名称包含 `时移专用`、`时移`。
- URL 不是合法 `rtp://组播IP:端口` 格式。
- 同一 RTP 地址重复出现。
- 频道名称为空。

`AVS2` 保留，不与 `CAVS` 混淆。

## 频道标准化与单源优选

每个标准频道只保留一条源。

标准化时去除不影响频道身份的质量和编码描述，包括：

- `4K`、`8K`、`UHD`、`超高清`、`超清`、`高清`、`HD`、`标清`、`SD`
- `25p`、`30p`、`50p`、`60p`
- `AVS2`、括号内编码或区域说明
- 多余空格、全角括号和重复分隔符

保留频道本体名称，例如：

- `广东卫视4k超高清25p` → `广东卫视`
- `广东体育（深圳）` → `广东体育`
- `CCTV-1高清` → `CCTV-1`

候选源排序分数按以下顺序确定：

1. `8K`
2. `4K` / `UHD`
3. `超清`
4. `高清` / `HD`
5. 无质量标识
6. `标清` / `SD`

同一质量等级存在多条源时，按以下稳定规则选择：

1. 优先频道名称更简洁、附加说明更少的条目。
2. 优先上游文件中靠前的条目。
3. 结果保持稳定，避免每次构建无意义切换地址。

## 分类规则

分类顺序固定为：

1. 央视
2. 卫视
3. 广东
4. 地方
5. 体育
6. 少儿
7. 电影电视剧
8. 纪录科教
9. 4K超高清
10. 其他

分类采用单一归属，按以下优先顺序判断：

- `4K超高清`：最终选中的频道名称或源描述含 `4K`、`8K`、`UHD`、`超高清`。
- `体育`：含 `体育`、`赛事`、`足球`、`篮球`、`高尔夫`、`台球`。
- `少儿`：含 `少儿`、`卡通`、`动画`、`金鹰卡通`、`嘉佳卡通`。
- `电影电视剧`：含 `电影`、`电视剧`、`剧场`、`影视`、`第一剧场`、`风云剧场`、`怀旧剧场`。
- `纪录科教`：含 `纪录`、`科教`、`探索`、`地理`、`兵器科技`、`世界地理`。
- `央视`：以 `CCTV`、`CGTN` 开头，或名称明确属于中央广播电视总台。
- `卫视`：名称含 `卫视`，广东卫视、深圳卫视等也归入卫视。
- `广东`：广东省级频道及名称含 `广东`、`珠江`、`大湾区`、`南方`、`岭南`、`嘉佳` 的频道。
- `地方`：广州、深圳及广东各地市频道。
- `其他`：未命中以上规则的频道。

这一顺序让体育、少儿、影视、纪录和 4K 等内容分类优先于机构分类。例如 `CCTV-5体育` 归入“体育”，`CCTV-4K` 归入“4K超高清”。

## M3U 输出格式

文件头：

```text
#EXTM3U name="广东电信IPTV" url-tvg="https://tv.shaowt.com/gd-telecom-epg.xml"
```

频道示例：

```text
#EXTINF:-1 tvg-name="广东卫视" group-title="卫视",广东卫视
http://192.168.5.7:4022/udp/239.77.0.66:5146/
```

第一阶段保留上游已有 `tvg-name`，频道显示名称采用标准化后的名称。EPG 文件在第一阶段可继续复制上游 `epg.xml`，输出为 `m3u/gd-telecom-epg.xml`。

## 自动更新

新增独立工作流：

```text
.github/workflows/update-gd-telecom-iptv.yml
```

北京时间每天执行两次：

- 06:30
- 18:30

GitHub Actions 使用 UTC cron：

```yaml
- cron: '30 22 * * *'
- cron: '30 10 * * *'
```

流程：

1. 检出当前仓库。
2. 下载上游 `GuangdongIPTV_rtp_all.m3u` 和 `epg.xml`。
3. 执行生成脚本。
4. 校验输出文件。
5. 只有 `gd-telecom.m3u`、EPG 或生成报告发生变化时才提交。
6. 推送后由现有 Cloudflare 部署发布 `m3u` 目录。

工作流支持手动触发。

## 生成脚本与报告

新增：

- `scripts/build-gd-telecom.mjs`
- `config/udpxy.json`
- `m3u/gd-telecom.m3u`
- `m3u/gd-telecom-epg.xml`
- `m3u/gd-telecom-report.json`

报告至少包含：

- 上游更新时间或提交 SHA
- 原始条目数
- 删除的 CAVS 数量
- 删除的时移数量
- 非法地址数量
- 标准化后频道数
- 去重前后数量
- 各分类频道数
- 每个频道最终选中源及淘汰候选数量

## 停用旧聚合链路

删除或停用以下自定义聚合功能：

- `custom.m3u` 及其候选、清洗、测速、网络配置等派生文件。
- 央视频测试文件和配置。
- 远程候选源抓取、CatVod 检查、官方候选合并等仅服务旧聚合源的流程。
- 原 `Refresh IPTV Candidates` 工作流。
- `package.json` 中旧聚合链路命令。

保留构建和 Cloudflare 发布所需的最小文件。删除前逐项检查引用，避免破坏 `m3u` 静态目录发布。

## 错误处理

- 上游下载失败：工作流失败，不覆盖现有播放列表。
- 输入为空或解析条目过少：工作流失败，不提交。
- udpxy 配置缺失或格式错误：构建失败。
- 生成后仍含 `rtp://`、`CAVS` 或 `时移`：构建失败。
- 同一标准频道出现多条输出：构建失败。
- 输出频道数明显低于合理阈值：构建失败并保留旧版本。

## 测试与验收

脚本单元测试覆盖：

- M3U 解析。
- CAVS 与时移过滤。
- `AVS2` 不被误删。
- 频道名称标准化。
- 4K、超清、高清、普通、标清的优选顺序。
- 单频道只输出一条。
- 分类优先顺序。
- udpxy 地址转换。

首次构建以用户上传的 `广东电信IPTV-全频道-HTTP.m3u` 作为对照，重点检查：

- CAVS 条目全部消失。
- 时移条目全部消失。
- 广东卫视、CCTV、深圳卫视等重复频道只保留一个。
- 输出 URL 均为 `192.168.5.7:4022/udp/` 格式。
- 分类适合电视端浏览。
