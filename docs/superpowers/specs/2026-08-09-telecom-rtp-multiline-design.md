# 广东电信 RTP 多线路主源设计

## 目标

将 `https://tv.shaowt.com/gd-telecom.m3u` 改为面向 MyIPTV 电视端的直接 RTP 组播主源。同一频道保留多条有效线路，并按画质从高到低排列；4K/8K重新进入主列表。现有 udpxy 输出保留为备用源，独立 4K 列表继续保留。

## 输出文件

- `m3u/gd-telecom.m3u`：新的 RTP 多线路主源，固定外部地址仍为 `https://tv.shaowt.com/gd-telecom.m3u`。
- `m3u/gd-telecom-udpxy.m3u`：旧式 udpxy 单线路备用源。
- `m3u/gd-telecom-4k.m3u`：独立超高清测试源，继续保留。
- `m3u/gd-telecom-epg.xml`：EPG 保持不变。
- `m3u/gd-telecom-report.json`：增加主源线路数、频道数和多线路统计。

## 主源数据规则

1. 从广东电信全量、HD 和 4K 上游列表提取 RTP/UDP 组播地址，并统一规范成 `rtp://IP:PORT`。
2. 继续过滤 CAVS、时移、回看、广告、测试卡、无节目、无效地址以及内容重复的“央视精品”。保留“央视文化精品”。
3. 相同 RTP 地址只保留一次。
4. 频道身份优先使用规范化后的 `tvg-name`，缺失时使用规范化频道名称。CCTV、CETV 等沿用现有标准化规则。
5. 同一频道保留全部有效 RTP 候选线路，不再只选一条最佳线路。
6. 同频道线路排序规则：8K > 4K > UHD/超高清 > 超清 > 高清 > 未标注 > 标清；同等级下主用优先于备用/测试，最后按上游顺序稳定排序。
7. 上游 4K/HD 专用列表继续作为画质证据；明确的频道名称画质标记优先。
8. 每条同频道线路输出相同的 `tvg-id`、`tvg-name`、频道显示名和 `group-title`，MyIPTV 可据此聚合为一个频道。
9. 主源直接输出 `rtp://` 地址，不经过 `192.168.5.7:4022`。

## 分组规则

- CCTV、CGTN 和央视系列频道统一归“央视”。
- “经济科教”归“广东”。
- `CCTV-4K`、`CCTV-8K`仍归“央视”。
- `广东4K`归“广东”。
- 普通卫视频道即使线路为4K，也继续归“卫视”，不因为画质进入独立“4K超高清”分组。
- 其他现有分组规则保持。

## udpxy 备用源

`gd-telecom-udpxy.m3u`继续使用当前 `config/udpxy.json` 的地址转换逻辑。备用源每个频道只保留排序后的第一条最佳线路，便于旧播放器兼容。`excludeUltraHd`不再控制 RTP 主源；备用源也默认允许4K，使主源和备用源的首选画质一致。

## 独立4K源

`gd-telecom-4k.m3u`继续只收录8K、4K、UHD、“超高清”及上游4K列表确认的线路，输出方式改为直接 RTP，与新的主源协议一致。

## 自动更新与验证

GitHub Actions 每天北京时间 06:30 和 18:30继续拉取上游。验证规则调整为：

- `gd-telecom.m3u` 必须包含 RTP 地址且不得包含 udpxy HTTP 地址；
- 至少存在一个频道有两条及以上 RTP 线路；
- 同频道线路按画质得分非递增排列；
- CAVS、时移、回看和广告不得进入任何输出；
- `gd-telecom-udpxy.m3u` 只能包含配置的 udpxy HTTP 地址；
- 独立4K源必须至少包含一个超高清频道；
- 现有央视、广东分组规则继续用测试锁定。

## MyIPTV 交接要求

本仓库不修改 MyIPTV。另一个会话中按以下接口适配：

- M3U 解析后按 `tvg-id` 优先、规范化 `tvg-name`/频道名兜底聚合同频道条目；
- `Channel.url` 使用第一条线路，`Channel.videoUrls` 保存完整有序线路列表；
- RTP 播放也必须读取 `videoUrls`，不能继续只使用单个 `channel.url`；
- 播放失败自动尝试下一条线路；
- 频道上下切换按聚合后的频道切换，不按线路切换；
- 保存上次播放时同时保留频道身份和当前线路，恢复失败时回退到该频道第一条可用线路。
